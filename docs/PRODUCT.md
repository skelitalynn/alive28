# 产品背景与范围

## 项目定位

HOPE 小希（代码仓库名 `alive28`）起源于 Web3 黑客松项目。产品希望通过连续 28 天的轻量任务、记录、反馈和阶段性凭证，帮助处于压力或低谷中的用户重新建立可执行的生活节奏。

当前实现是自我反思工具，不是医疗产品：

- 不进行心理或医学诊断。
- 不提供治疗方案或用药建议。
- 不替代心理咨询师、医生或紧急救援。
- 当前版本尚未实现可靠的危机识别与人工升级链路。

## 用户旅程

1. 用户通过钱包或手动地址进入应用。
2. 每天读取一个固定任务并写下感受。
3. 后端生成包含 `note` 和 `next` 的 AI 反馈。
4. 系统保存日志、更新连续天数和里程碑资格。
5. 用户查看周报或 28 天结营报告。
6. 用户可选提交链上 Proof，并铸造 Day、Final 或里程碑 NFT。

链上哈希仅表示某地址提交过一个承诺值，不证明任务真实完成，也不证明用户的心理状态。

## 28 天内容框架

产品叙事将任务分为三个主题：

- 自我照顾：饮食、睡眠、呼吸、减负、情绪接纳和允许脆弱。
- 自我认可：看见努力、确认价值、接纳平凡和回顾成长。
- 关系连接：表达需求、接受帮助、给予善意和建立边界。

实际每日任务以 `backend/app/data/tasks.json` 为准；修改任务时需要同步检查 Prompt、报告和前端展示。

## 当前能力

- 28 天固定任务。
- AI Reflection 反馈。
- 连续天数、完成天数和里程碑状态。
- 周报与结营报告。
- 钱包连接或手动地址。
- 可选 Proof 与 NFT 合约流程。
- 基于用户记录生成 NFT 图片。

## 非目标与未完成能力

- 未实现专业心理评估。
- 未实现自伤或他伤场景的可靠危机路由。
- 未实现钱包签名认证。
- 未验证客户端上报的链上交易回执。
- 未实现日记加密、脱敏、保留期和删除流程。
- 未实现图片输入 OCR。

## 历史商业化假设

原始黑客松方案提出过以下方向，当前仓库没有实现对应商业系统：

- Free、Pro、Plus 和机构订阅。
- 链上人生阶段凭证。
- 28 天内容协议和 IP 授权。
- 面向焦虑管理、关系修复或职业转型的垂直 Agent。

这些内容属于产品假设，不应在技术文档中表述为已交付能力。
